# The AC Lab — Main Website Upgrade v4

รุ่นนี้พัฒนาต่อจาก **AC Lab Smart Member Registration v3** และยังคงระบบ Submit/Manager/Supabase เดิมไว้ เพื่อให้การเปลี่ยนเว็บไซต์หลักไม่ทำให้ข้อมูลหรือคิวอนุมัติสูญหาย

## สิ่งที่เปลี่ยนบนเว็บไซต์หลัก

- **Lab Directory v4:** แสดงสมาชิกจากข้อมูลที่ผู้ดูแลอนุมัติแล้วแบบรวมทุกประเภท ไม่ต้องเปิดหน้า PhD เท่านั้นก่อน
- **ค้นหา:** ชื่อไทย/อังกฤษ มหาวิทยาลัย คณะ หลักสูตร ปีฝึกงาน ปีเข้าศึกษา วิทยานิพนธ์ เทคนิค และคำสำคัญจากโครงการวิจัย
- **ตัวกรอง:** All, PhD, Master's, Internship, Staff & Assistants (รวม Research Assistant/Postdoc), Alumni (แยก Master's/PhD เพิ่มเติม)
- **เรียงลำดับ:** ลำดับเดิม, A–Z, Z–A และปีล่าสุด
- **สถิติจริง:** จำนวนสมาชิกแล็บ นักศึกษาฝึกงาน นักศึกษาบัณฑิตศึกษา และบุคลากร — คำนวณจากชุดข้อมูล MEMBERS ที่ผ่านการเผยแพร่แล้ว ไม่ใช้ตัวเลขจำลอง
- **การ์ดโปรไฟล์:** ภาพสมาชิก, ชื่อไทย/อังกฤษ, ประเภท, สังกัด, โครงการฝึกงาน/วิทยานิพนธ์/หน้าที่, แท็ก และเปิดดูรายละเอียดใน modal
- **ลิงก์ตรงจากเว็บหลัก:** หน้าแรก, Lab Directory และ Join the Lab นำไปยัง `/submit/?category=team` ได้โดยตรง หรือ `/submit/?category=team&action=update` เพื่อเลือกขอแก้ไขข้อมูลเดิม
- **สองภาษา:** ข้อความเพิ่มใหม่รองรับไทย/อังกฤษตามปุ่มเปลี่ยนภาษาของเว็บไซต์
- **รองรับมือถือ:** แถบค้นหา ตัวกรอง การ์ด และปุ่มปรับตามความกว้างของจอ
- **ความสามารถใช้งาน:** เพิ่มปุ่มข้ามไปเนื้อหา, สถานะผลค้นหา, แป้นพิมพ์ Enter/Space เปิดโปรไฟล์, ปรับลดแอนิเมชันตามตั้งค่าระบบ
- **แก้โค้ดเว็บเดิม:** ลบ `adminContent` ที่ซ้ำและ closing tags ส่วนเกิน โดยไม่เปลี่ยนวิธีเข้าสู่ระบบ CMS

## ติดตั้ง / อัปเกรดจาก v3

1. สำรองไฟล์ `index.html`, `admin-addon.js` และฐานข้อมูล Supabase ก่อนอัปเดต
2. อัปโหลดไฟล์ `index.html`, `main-v4.css`, `main-v4.js`, `admin-addon.js` และโฟลเดอร์ `submit/` โดย **คงโครงสร้างโฟลเดอร์และชื่อไฟล์** ดังตัวอย่าง
3. **อย่าลบโฟลเดอร์เดิมของเว็บไซต์** เช่น `/shop/`, `/awards/` หรือ `/portfolio/` เพราะลิงก์บนเว็บหลักยังอ้างถึงเว็บย่อยเดิม โฟลเดอร์เหล่านี้ไม่ได้บรรจุมาใน ZIP นี้
4. หากใช้งาน v3 กับ Supabase ได้อยู่แล้วไม่จำเป็นต้องสร้างตารางใหม่ แต่ต้องมั่นใจว่า `site_content` เปิด `SELECT` สำหรับผู้ชมและอนุญาตให้แก้ข้อมูลเฉพาะผู้ดูแลที่ได้รับสิทธิ์เท่านั้น
5. หากยังไม่เคยติดตั้งโมดูล Submission ให้รัน `supabase/setup.sql` และเพิ่มบัญชีผู้ดูแลใน `cms_admin_users` ตามคู่มือด้านล่าง
6. ลองเปิด `https://<your-domain>/#members`, ค้นหาสมาชิก กดดูโปรไฟล์ กดส่งข้อมูล และตรวจคิว `Manager → Submissions`
7. ทดสอบบัญชีผู้ดูแลกับ Supabase จริงก่อนเปิดใช้ในระบบที่มีผู้ส่งจำนวนมาก หลีกเลี่ยงการรัน SQL/ทับไฟล์ข้อมูลโดยไม่สำรอง

**การเก็บภาพ:** ให้ส่งภาพผ่านลิงก์ Google Drive ที่เจ้าของภาพอนุญาตให้เผยแพร่ ตั้งค่าเป็น “ทุกคนที่มีลิงก์ → ผู้ดู” และใส่ URL ในฟอร์ม ระบบเก็บ URL ไม่เก็บเนื้อภาพ จึงลดการใช้พื้นที่ข้อมูล (ลิงก์บางแบบอาจไม่แสดงภาพเมื่อ Google Drive จำกัดการเข้าถึง/การแสดงผล)

**การทดสอบในชุดที่ส่งมอบ:** ตรวจ syntax ของ JavaScript, องค์ประกอบ HTML/ID ที่ซ้ำ และจำลองการเรนเดอร์/ค้นหา/กรอง/เปลี่ยนภาษาของ Directory สำเร็จ ยังไม่ได้ทดสอบระบบบนโฮสต์จริงหรือสั่งเขียน Supabase ของผู้ใช้โดยตรง เบราว์เซอร์ที่มีให้ในสภาพแวดล้อมนี้จำกัดการเปิด URL จึงยังไม่ได้ตรวจภาพแบบ end-to-end ในเบราว์เซอร์จริง

### การใช้งานใน Manager

- คำขอทุกกลุ่มเข้าแท็บ **Submissions** พร้อมป้ายประเภท; ผู้ดูแลตรวจและแก้ไขข้อมูลในฟอร์มเฉพาะกลุ่มก่อนอนุมัติได้
- หลังอนุมัติจะถูกเก็บเป็นข้อมูลสมาชิกที่มี fields เฉพาะประเภท พร้อมแสดงปีฝึกงาน/โครงการ/วิทยานิพนธ์ในหน้าสมาชิกและ modal โปรไฟล์
- แท็บ **Team** รองรับการแก้ไขรายละเอียดเฉพาะประเภทต่อจากข้อมูลเดิมแล้ว (ไม่ลบ field เฉพาะประเภทเมื่อแก้โปรไฟล์)
- เพิ่มตัวกรอง **Staff & Assistants** ที่หน้าสมาชิกของเว็บหลัก
- หมวดเก่าอื่น ๆ ทั้ง 20 หมวดยังเปิดใช้งานผ่านเมนู **ข้อมูลเว็บไซต์อื่น ๆ** แต่ให้ความสำคัญกับข้อมูลบุคลากรอันดับแรก

**การติดตั้ง:** ใช้ไฟล์ `supabase/setup.sql` ของชุดนี้เหมือน v2 (ไม่จำเป็นต้องเปลี่ยนตารางสำหรับฟอร์มบุคลากร เพราะข้อมูลอยู่ใน `payload` JSONB ภายใต้ category=`team`) หากเคยรัน SQL v2 แล้ว ตารางเดิมใช้งานต่อได้ ไม่ต้องลบข้อมูลเดิม

## ขั้นตอนติดตั้งจริง (สำคัญ)

1. สำรองเว็บไซต์และฐานข้อมูลเดิมก่อนนำไฟล์ใหม่ขึ้นโฮสต์
2. เข้า **Supabase → SQL Editor** บนโปรเจกต์เดิม (`nmzwvxdegtfartbhoixx` ตามค่าในไฟล์เดิม) คัดลอกและ Run ไฟล์ `supabase/setup.sql` **เพียงครั้งแรก**
3. ใน **Supabase → Authentication → Users** ตรวจว่ามีบัญชีผู้ดูแลที่ได้รับอนุญาตแล้ว
4. ที่ SQL Editor รันต่อโดยแทน `YOUR_ADMIN_EMAIL` ด้วยอีเมลบัญชีผู้ดูแลจริง:

   ```sql
   insert into public.cms_admin_users(user_id)
   select id from auth.users where lower(email)=lower('YOUR_ADMIN_EMAIL')
   on conflict(user_id) do nothing;
   ```

   อย่าอนุญาตบัญชีที่ไม่ใช่ผู้ดูแลจริง แม้ว่าบุคคลนั้นจะมี Supabase Auth login อยู่ก็ตาม
5. **ตรวจสิทธิ์ RLS ของตาราง `site_content` เดิม** ด้วยคำสั่งนี้; ต้องเปิดให้ public SELECT แต่ UPDATE ต้องเฉพาะ trusted admins เท่านั้น หากเดิมมี policy ที่อนุญาต `anon` UPDATE ต้องยกเลิก:

   ```sql
   select tablename, policyname, roles, cmd, qual, with_check
   from pg_policies
   where schemaname='public' and tablename in ('site_content','content_submissions')
   order by tablename, policyname;
   ```

   **ไฟล์ SQL นี้จะไม่ไปลบหรือแก้ policy เดิมของ `site_content`** เพื่อป้องกันระบบเดิมเสียหาย ผู้ดูแลฐานข้อมูลต้องตรวจสิทธิ์แยกต่างหากก่อนใช้งานจริง
6. อัปโหลด `index.html`, `admin-addon.js` และโฟลเดอร์ `submit/` ทั้งชุดลง **root ของเว็บไซต์เดิม** โดยคงโฟลเดอร์เดิม เช่น `awards/`, `shop/`, `portfolio/` ไว้ ถ้าทำไว้แล้ว (โฟลเดอร์เหล่านี้ไม่ได้อยู่ในไฟล์ที่แนบครั้งนี้)
7. เปิดเว็บผ่าน **HTTPS** ไม่ควรทดสอบการเชื่อม Supabase ผ่านการ double-click เปิดไฟล์ `file://` โดยตรง
8. ทดลองส่งคำขอสั้น ๆ จาก `/submit/` → ล็อกอิน Manager → Submissions → ตรวจ/อนุมัติ → เปิดเว็บหลักใหม่เพื่อยืนยันว่าข้อมูลขึ้นจริง

**โปรดทราบ:** ยังไม่ได้มีการรัน SQL บนโปรเจกต์ Supabase ของคุณหรืออัปโหลดไฟล์ขึ้นเว็บไซต์จริง ชุดนี้เป็นไฟล์พร้อมนำไปติดตั้ง (v3) ซึ่งจะบันทึกจริงได้หลังตั้งค่าตารางและ RLS ตามขั้นตอนด้านบน

## รูปภาพ: ทำอย่างไรให้ประหยัดฐานข้อมูล

1. เปิด Google Drive อัปโหลดภาพ JPG/PNG/WEBP
2. คลิกขวารูปภาพ → แชร์ → การเข้าถึงทั่วไป → **ทุกคนที่มีลิงก์ (Anyone with the link)** → **ผู้ดู (Viewer)**
3. คัดลอก URL เช่น `https://drive.google.com/file/d/FILE_ID/view?usp=sharing`
4. วางลงช่องรูปภาพ โปรแกรมจะแปลงเป็น `https://drive.google.com/thumbnail?id=FILE_ID&sz=w1600`
5. ตรวจดูตัวอย่างภาพ ผู้ดูแลควรเปิดตรวจภาพอีกครั้งก่อนอนุมัติ

วิธีนี้เก็บ URL ในฐานข้อมูลแทนไฟล์รูปภาพขนาดใหญ่ แต่ Google Drive **ยังคงมีข้อจำกัดด้าน bandwidth/การแสดงภาพ** และผู้ที่มีลิงก์สามารถเปิดไฟล์ได้ จึงควรใช้กับรูปที่ตั้งใจเผยแพร่สาธารณะเท่านั้น หากเว็บมีผู้เข้าชมจำนวนมาก ควรพิจารณา CDN/รูปภาพโฮสต์แยกที่เหมาะกับการเผยแพร่สาธารณะ

## ข้อควรทราบก่อนเปิดใช้งานในวงกว้าง

- SQL มี RLS และจำกัดเบื้องต้นที่ **5 คำขอจากอีเมลเดียวกันใน 30 นาที** แต่ยังไม่ใช่ระบบป้องกันบอตสมบูรณ์ การเผยแพร่สาธารณะในวงกว้างควรเสริม Turnstile + Edge Function ตรวจ token ฝั่งเซิร์ฟเวอร์, quota และ monitoring
- หน้า Manager เดิมต้องอาศัยบัญชี Supabase Auth และกลไก Turnstile Worker เดิมจึงจะล็อกอินได้ ไม่ได้ลบออก
- **ไม่มีการอัปโหลดไฟล์รูปภาพเข้า Supabase Storage** ผ่านหน้าฟอร์มใหม่: ใช้ลิงก์ URL ตามที่ร้องขอ
- การเปลี่ยนธีมหลัก, การแก้ข้อความทั่วเว็บ และการลบ/จัดโครงสร้างหน้าเว็บไซต์ยังต้องทำผ่าน Manager เท่านั้น เพื่อไม่ให้ผู้ส่งสาธารณะปรับการตั้งค่าเว็บไซต์ได้โดยตรง
- การอนุมัติรายการบางประเภทอาจต้องตรวจลิงก์/รูปแบบเนื้อหาด้วยตนเอง เช่น ชื่อวิทยาศาสตร์ ลิงก์ DOI ป้ายผลิตภัณฑ์ และข้อความอ้างอิง
- เนื้อหาเว็บเดิมที่อ้างพาธหรือเว็บย่อยอื่นต้องคงโฟลเดอร์ไฟล์เดิมบนโฮสต์ เว็บย่อยเหล่านั้นไม่ได้ถูกสร้างซ้ำจากไฟล์แนบเพียงไฟล์เดียว
